## Goals / Non-Goals

**Цели:** сосредоточить защиту записи в общей границе публикации, сохранить семантику форматирования,
запретить встраивание независимо от результата HTTP-запроса и закрепить исполняемые зависимости выпуска.

**За пределами проектного решения:** универсальная изоляция файловой системы от враждебного процесса с теми же
правами, конкурентная подмена родительских каталогов, новая авторизация API, ограничения размера входных файлов,
перенос моделей, обновление зависимостей, изменение транспорта OpenAI и запуск выпуска.

## Decisions

### 1. Последовательный подсчёт скобок

В [line_utils.py](../../../../sub_translate/utils/line_utils.py) сохранить сначала действующую обработку точек.
Для последующего обхода совпадений `?`/`!` использовать монотонно продвигаемый курсор по полученной строке и
знаковый баланс круглых скобок. Каждый символ учитывается ограниченное число раз; проверка положения очередного
знака не создаёт срез и не пересчитывает весь префикс. Отрицательный баланс сохраняется.
Условия для латиницы, кириллицы и допустимых закрывающих символов остаются прежними.

Альтернативы: ограничить длину реплики — меняет допустимые входы; запоминать ответ отдельно для каждой позиции —
не устраняет повторные обходы; массив балансов для всех позиций — корректен, но требует линейной дополнительной
памяти. Выбран последовательный проход с постоянным состоянием помимо создаваемой выходной строки.

### 2. Публикация субтитров без разрешения конечной ссылки

В [service.py](../../../../sub_translate/service.py) сохранять для обоих видов выхода канонический родительский
каталог и имя конечного компонента, не разрешая сам конечный компонент. Изменить также передачу вычисленного пути
из [CLI](../../../../sub_translate/cli.py), чтобы раннее разрешение ссылки не стирало сведения о назначении.
Проверять ссылочность через метаданные самого элемента, включая отсутствующую цель ссылки и атрибут
`FILE_ATTRIBUTE_REPARSE_POINT` в Windows; проверка через `exists()` или `is_file()` недостаточна.
Существующий обычный выход сравнивать с исходником по файловой идентичности, чтобы учесть жёсткие ссылки.

В [io_utils.py](../../../../sub_translate/utils/io_utils.py) выделить общий внутренний механизм атомарной записи
и тонкий вход для публикации субтитров с защищаемым исходником. Новый перевод через `write_lines` и восстановление
в [subtitle_cache.py](../../../../sub_translate/utils/subtitle_cache.py) должны использовать этот вход;
для кеша исходник доступен в `OutputCacheIdentity.source_path`. Проверка назначения выполняется до обработки,
перед решением о восстановлении кеша и повторно под выходной блокировкой перед каждой попыткой публикации.
При восстановлении сохраняется также запрет назначения, совпадающего с файлом кеша.

Имя блокировки выводится из уже нормализованных родителя и конечного имени: повторный `resolve()` конечного
компонента в `_output_lock_path` недопустим. Временный файл создаётся исключительно (`open('x')`) рядом с выходом,
сохраняя случайное имя, UTF-8 без BOM, синхронизацию и ограниченные повторы `PermissionError`.
Замена работает с конечным именем, не с разрешённой целью ссылки. Если ссылка подставлена после последней проверки,
допустима замена самой записи ссылки обычным результатом либо безопасный отказ; следование к её цели запрещено.
Обнаруженная перед заменой ссылка вызывает отказ. Реальные свойства замены проверяются на поддерживаемой Windows.

У `atomic_write_json` и остальных несубтитровых потребителей сохраняется прежняя семантика. Модельная отметка
не переводится на новый путь записи. Ошибка публикации не создаёт запись успешного результата в готовом кеше.
Восстановление кеша не должно терять проверку ссылки из-за собственного раннего разрешения пути.

Альтернативы: только ранний `resolve()` закрывает заранее созданную ссылку на исходник, но разрешает ссылки на
сторонние файлы и сохраняет окно до записи; только проверка в веб-обработчике оставляет прямой сервис и кеш;
глобальное изменение всех JSON-записей расширяет объём. Выбран общий путь публикации именно субтитров.

Это развивает ответственность общего сервиса из
[ADR-001](../../../context/ADR/ADR-001-single-service-and-profile-registry.md). Модель владения весами из
[ADR-003](../../../context/ADR/ADR-003-fingerprint-and-safe-model-publication.md) не пересматривается.

### 3. Неизменяемые прямые зависимости выпуска

В [python-publish.yml](../../../../.github/workflows/python-publish.yml) заменить существующие ссылки:
`actions/checkout@v4`, `actions/setup-python@v5`, `astral-sh/setup-uv@v7`,
`actions/upload-artifact@v4`, `actions/download-artifact@v4`, `pypa/gh-action-pypi-publish@release/v1`.
Для каждой получить полный SHA коммита из официального репозитория на момент реализации; для аннотированного тега
получить конечный commit, а не SHA объекта тега. Сохранить прежний ref комментарием и зафиксировать проверенное
соответствие в доказательстве реализации.

Новый `tests/test_release_workflow.py` использует стандартную библиотеку: проверяет все объявления `uses`,
ожидаемые шесть Actions и полный SHA. Неподдержанная форма объявления не должна молча пропускаться. Конкретные SHA
не дублируются вторым списком в тесте; положительные и отрицательные варианты проверяют правило закрепления.
Локальная проверка не подтверждает происхождение коммита или доступность PyPI — это отдельные слои.

Альтернатива — файл закрепления транзитивных зависимостей workflow. Он даёт более широкий контроль, но вводит
отдельный механизм сопровождения. Для этого изменения выбран минимальный вариант прямых SHA, предусмотренный
[рекомендациями GitHub](https://docs.github.com/en/actions/reference/security/secure-use).

### 4. Запрет встраивания на внешней границе HTTP-ответа

Добавить `Content-Security-Policy: frame-ancestors 'none'` и `X-Frame-Options: DENY` на внешней границе приложения,
охватывающей статические файлы, ранний HTTP 403 и ответы обработчиков ошибок, включая HTTP 500.
Предпочтителен небольшой ASGI-обёртчик вокруг всего приложения, изменяющий только событие начала HTTP-ответа;
объект FastAPI для регистрации маршрутов и тестов сохраняется доступным. Само добавление заголовков в `index()`
или только после `call_next` недостаточно для всех путей ошибок. Поток SSE, тела и статусы не меняются.

Политика задаётся HTTP-заголовком: `frame-ancestors` не действует из HTML meta. Она запрещает встраивание и с того
же источника, что даёт однозначную проверку. Существующая проверка адреса, Host и переданного Origin сохраняется;
доверенный локальный клиент без Origin не получает новую обязанность аутентификации.
Семантика директивы описана в [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).

В браузерном наборе использовать верхнюю страницу с другого loopback-порта. Положительный контроль без политики
должен доказать, что окружение позволяет загрузить тестовый iframe. Затем проверить реальный ответ приложения
с политикой: документ интерфейса не становится доступным во фрейме и управляющий запрос из него не отправляется.
Обычную верхнюю вкладку проверить отдельно. Тест не зависит от публичного сайта и не выдаёт блокировку локальной
сети браузером за доказательство действия CSP.

Альтернативы: проверка `window.top` выполняется слишком поздно и не заменяет политику браузера; авторизация API
не предотвращает клики по уже авторизованному интерфейсу и не соответствует выбранной модели доверия.

## Risks / Trade-offs

- Недоступное создание ссылок в Windows → отдельно отмечать пропуски настоящих файловых сценариев; заглушка
  метаданных не считается полноценной проверкой файловой системы. Приёмка ссылочной защиты остаётся неполной
  до прогона на среде с разрешёнными ссылками; права и режим разработчика автоматически не изменяются.
- Подмена родительского каталога враждебным процессом → исключена выбранной моделью угроз. Проверки конечной
  ссылки не объявляются универсальной защитой от всех гонок файловой системы.
- Случайная смена форматирования → сопоставлять точные строки на граничных примерах и существующем наборе;
  преобразование сохраняет семантику, поэтому версия алгоритма готового кеша остаётся прежней.
- Блокировка iframe самим браузером → положительный контроль; при его неуспехе результат `NOT_RUN` или `partial`,
  а не подтверждение исправления CSP.
- Синтаксически правильный SHA чужого происхождения → проверять соответствие официальному upstream отдельно;
  закрепление прямых Actions не объявляется проверкой всего транзитивного кода.

## Migration Plan

Миграция пользовательских данных и модельных каталогов не требуется. Владельцу ссылочного назначения нужно выбрать
обычный выходной файл; интерфейс открывается отдельной вкладкой.
Для совместного завершения четырёх исправлений до итоговых проверок повысить актуальную минорную версию один раз
по правилу `M.m.p → M.(m+1).0`. Синхронизировать источник версии пакета, версию приложения, метаданные сборки и
анализа, текущую спецификацию и CHANGELOG. Новая версия исходников не подтверждает публикацию или развёртывание.
Синхронизировать дельты в текущие спецификации с корректными относительными ссылками; результаты приёмки должны
относиться к окончательному содержимому с обновлённой версией.

Порядок приёмки: целевые регрессии, полный набор Python с покрытием, браузерный набор, Ruff, компиляция и сборка,
затем свежий Sonar по [проектной процедуре](../../../specs/engineering-governance/reference/project-specific.md).
Проверки выполняются в поддерживаемой среде из Windows PowerShell 5.1. Если `uv` недоступен, это фиксируется отдельно;
прямой запуск существующей `.venv` не доказывает синхронизацию полного закреплённого графа.
Реальные модели, внешние API, выпуск/OIDC/PyPI и повторное облачное сканирование не входят в эту приёмку.

Изменения применяются отдельными проверяемыми частями. При регрессии откатывается затронутая часть без миграции
файлов; соответствующее замечание снова считается открытым. Откат нельзя выдавать за успешное исправление.
