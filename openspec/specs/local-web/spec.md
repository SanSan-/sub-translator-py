# local-web Specification

## Purpose

Локальная пакетная работа с субтитрами через проверяемый выбор, наблюдаемую подготовку, общий конвейер и авторитетное
состояние задачи.

## Requirements

### Requirement: WEB-001 Локальная граница и схемы

Веб-сервис SHALL по умолчанию слушать 127.0.0.1 и требовать петлевой адрес клиента и адресуемого узла (`Host`);
переданный источник изменяющего запроса (`Origin`) должен совпадать с текущим узлом. Заголовки перенаправления
(`Forwarded`) MUST NOT доказывать локальность. Все локальные API-клиенты считаются доверенными; отсутствие `Origin`
у локального клиента SHALL допускаться без отдельной авторизации. Схема SHALL отклонять неизвестные поля;
ограничения на секреты определяются
[SUB-010](../subtitle-translation/spec.md#requirement-sub-010-настройки-секреты-и-cli).
Ответ HTTP 422 не отражает входные значения; пустые необязательные пути нормализуются в `null`.

Каждый HTTP-ответ приложения, включая статические ресурсы, ранние отказы и ошибки, SHALL содержать
`Content-Security-Policy` с `frame-ancestors 'none'` и `X-Frame-Options: DENY`. Интерфейс MUST NOT допускать
встраивание в другую страницу; обычное открытие в отдельной вкладке SHALL сохранять работоспособность.
Запрет встраивания не заменяет проверку клиента, Host и переданного Origin.

#### Scenario: Локальная граница и схемы

- **WHEN** изменяющий запрос содержит внешний Origin
- **THEN** операция отвергается без старта перевода или выгрузки.

#### Scenario: Пустые пути файлов подсказок

- **WHEN** `agent_system_prompt_file` или `agent_prompt_file` содержит пустую строку либо только пробелы
- **THEN** схема нормализует значение в `null`; чтение файла по этому значению не выполняется.

#### Scenario: Доверенный локальный клиент без Origin

- **GIVEN** адрес клиента и Host допустимы и остальные условия операции выполнены
- **WHEN** локальный клиент отправляет изменяющий запрос без Origin
- **THEN** отсутствие Origin само по себе не вызывает отказа и не требует нового секрета доступа.

#### Scenario: Политика присутствует на отказах

- **WHEN** приложение возвращает обычный ответ, статический ресурс либо отказ HTTP 403, 404, 422, 500 или 503
- **THEN** оба заголовка запрета встраивания присутствуют; статус, тело и допустимые побочные эффекты операции
  сохраняют собственный контракт.

#### Scenario: Встраивание из другого источника

- **GIVEN** браузер может обратиться к локальному приложению и верхняя страница имеет другой источник
- **WHEN** верхняя страница пытается загрузить интерфейс в iframe
- **THEN** браузер блокирует встраивание по политике приложения; элементы управления и их операции недоступны
  через этот iframe.

#### Scenario: Самостоятельная вкладка

- **WHEN** пользователь открывает локальный интерфейс как верхнюю страницу
- **THEN** интерфейс загружается и разрешённые операции остаются доступны.

### Requirement: WEB-002 Детерминированный выбор

Локальные пути SHALL выбираться через системный диалог. Выбор папки SHALL рекурсивно собирать ASS/SRT/VTT, не переходить
по символическим ссылкам и точкам соединения (`symlink`/`junction`), сохранять доступных соседей при ошибке ветви,
дедуплицировать и сортировать результат. Явный выбор файлов нерекурсивен. Предел MUST быть 10000 файлов. При выборе папки
точный суффикс целевого языка исключается, обычные .cc/.web не исключаются.

#### Scenario: Детерминированный выбор

- **WHEN** найдено 10001 допустимых файлов
- **THEN** выбор отклоняется до перевода; пользователь получает наблюдаемую ошибку.

### Requirement: WEB-003 Подготовка и настройки

Подготовка SHALL иметь поколение, непрозрачный ID, фазу, неубывающие счётчики, ограниченный журнал и терминальную
ошибку. Повторный выбор/старт блокируются до завершения подготовки; изменение настроек MUST NOT запускать скрытый обход.
Применимость настройки CPU определяется [MODEL-006](../model-runtime/spec.md#requirement-model-006-nllb-и-изолированные-профили).

#### Scenario: Подготовка и настройки

- **WHEN** позднее событие предыдущего поколения приходит после нового выбора
- **THEN** оно не меняет состояние новой подготовки.

### Requirement: WEB-004 Авторитетная задача

Одновременно SHALL работать одна пакетная задача. Сервер SHALL предоставлять ограниченный снимок активной и недавно
завершённой задачи без перечитывания субтитров. После разрыва потока серверных событий (SSE) клиент MUST восстановить
итог и журнал конкретной задачи по снимку сервера и проверить новую активную задачу перед снятием блокировки.
Готовность файла определяется результатом общего конвейера по
[SUB-002](../subtitle-translation/spec.md#requirement-sub-002-выход-и-force).

#### Scenario: Авторитетная задача

- **WHEN** событие завершения старой задачи пришло после старта новой в другой вкладке
- **THEN** новая задача остаётся активной и интерфейс не разблокируется по старому событию.

### Requirement: WEB-005 Ограничение представления и отказ

Клиент SHALL сохранять весь выбранный набор при отображении не более 200 карточек одновременно. Отказ создания или
запуска обработчика MUST возвращать безопасный HTTP 503 без зарегистрированной задачи и освобождать слот.
Ошибка подготовки уже принятой задачи, включая создание журнала, SHALL завершать её состоянием `error` и
освобождать слот; незавершённые элементы терминальной задачи не остаются в очереди.

#### Scenario: Отказ запуска обработчика

- **WHEN** обработчик задачи не запустился
- **THEN** сервер возвращает безопасный HTTP 503, задача отсутствует в реестре и слот свободен;
  новая разрешённая задача может быть запущена.

#### Scenario: Ошибка подготовки принятой задачи

- **WHEN** при подготовке уже принятой задачи не удалось создать журнал
- **THEN** задача и её незавершённые элементы имеют состояние `error`, слот освобождён;
  новая разрешённая задача может быть запущена.
