# Ограничения и проверки sub-translator-py

Приложение задаёт процедуры проверки требований [инженерной спецификации](../spec.md).

## Пользовательские сообщения и настройки

Пользовательская ошибка выводится по-русски; диагностическая трассировка не служит основным ответом.
Имена переменных окружения и переносимые примеры значений находятся в [.env.example](../../../../.env.example).
Работа с ключами, настройками и диагностикой определяется [SUB-010](../../subtitle-translation/spec.md#requirement-sub-010-настройки-секреты-и-cli).

## Среда и команды

Источники версий, платформы и закреплённого графа зависимостей определены в
[ENG-001](../spec.md#requirement-eng-001-воспроизводимая-среда-переводчика).
Изолированные профили используют декларативные зависимости реестра по [MODEL-001/006](../../model-runtime/spec.md).

Команды выполняются из корня проекта в соответствующей задаче. `uv sync --frozen` подготавливает среду с
зависимостями разработки; рабочая установка без них — `uv sync --frozen --no-dev`.

```powershell
uv lock --check
uv sync --frozen
uv pip check
uv run --frozen python -m pytest -p no:cacheprovider -q
uv run --frozen python -m pytest -p no:cacheprovider -q --cov=sub_translate --cov-branch --cov-report=term-missing --cov-report=xml:coverage.xml
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen python -B -m compileall -q sub_translate tests tools
uv build
node --check sub_translate/web/static/app.js
```

Браузерный набор выполняется из `tests/e2e` командой `npm test` в подготовленной среде. Для изменения JavaScript
нужны проверка синтаксиса и применимый браузерный сценарий.

## Приёмка моделей и качества

Для тяжёлых TranslateGemma 12B и Seed-X используются `RUN_HEAVY_LOCAL_MODEL_INTEGRATION=1` и четыре переменные путей:

- `SUB_TRANSLATOR_TRANSLATEGEMMA_12B_MODEL_PATH`;
- `SUB_TRANSLATOR_TRANSLATEGEMMA_12B_WORKER_PYTHON`;
- `SUB_TRANSLATOR_SEEDX_MODEL_PATH`;
- `SUB_TRANSLATOR_SEEDX_WORKER_PYTHON`.

До включения подготовьте совместимые среды по [MODEL-001/006](../../model-runtime/spec.md), каталоги полных локальных
моделей и существующие исполняемые файлы Python. Интеграционные тесты других профилей сохраняют собственные условия включения.
Критерии сравнения и приёмки находятся в [ENG-002](../spec.md#requirement-eng-002-проверки-и-критерии-приёмки-переводчика).

### Корпусное сравнение

Измерение выполняет [benchmark_translators.py](../../../../tools/benchmark_translators.py) из корня проекта после
подготовки среды с зависимостями разработки и с доступной CUDA. Переход на CPU в этой процедуре отключён.
Заранее задайте путь к локальной модели, действительный JSON-корпус для выбранного направления и новый выходной
JSON-файл. Для изолированного профиля подготовьте его Python и добавьте `--worker-python-path "<worker-python-path>"`.
Входной корпус и существующие отчёты не используются как выходной файл.

Корпус содержит непустую строку `name` и объект `directions`. Для выбранного ключа `en-ru` или `ru-en` требуется
непустой список объектов с непустыми строками `source` и `reference`. Необязательное поле `required_terms` — список
непустых строк без повторов после нормализации, используемой инструментом.

Инструмент вызывает адаптер напрямую и измеряет перевод строк, качество и ресурсы. Общий сервис, кеш и безопасные
отказы проверяются отдельно по [контрактам перевода](../../subtitle-translation/spec.md), синтаксис и структура файлов —
по [SUB-003…006](../../subtitle-translation/spec.md).

Пример для NLLB, направление EN→RU:

```powershell
$env:HF_HUB_OFFLINE = "1"
$env:TRANSFORMERS_OFFLINE = "1"
uv run --frozen python tools/benchmark_translators.py --translator nllb-600m --direction en-ru --model-path "<local-nllb-model-path>" --corpus "<corpus-json>" --limit 12 --batch-size 4 --timeout 1800 --output "<new-report-json>"
```

Для других профилей замените идентификатор, модельный путь, параметры из таблицы и добавьте Python изолированной среды.
Для RU→EN укажите `--direction ru-en` и отдельный новый выходной файл.

| Профиль | Размер пачки | Предел времени, с | Изолированная среда |
|---------|--------------|--------------------|--------------------|
| `nllb-600m` | 4 | 1800 | Не требуется |
| `translategemma` | 4 | 1800 | Требуется |
| `translategemma-12b` | 4 | 3600 | Требуется |
| `seedx` | 1 | 3600 | Требуется |

Первичные результаты прежних измерений при их наличии хранятся в локальном каталоге `docs/benchmarks/results`.

## Sonar

Анализ после стабилизации кода использует `sonar-scanner` из корня. `SONAR_TOKEN` передаётся только через окружение,
не через `-Dsonar.token`. Проверяются SECURITY, ошибки, уязвимости, сопровождаемость и дублирование.
Условия покрытия и шлюза качества заданы [ENG-002](../spec.md#requirement-eng-002-проверки-и-критерии-приёмки-переводчика).

## Указатели на предметные контракты

| Область | Единственный источник требований |
|---------|----------------------------------|
| Форматы, публикация, кеши, поставщики и настройки | [SUB-001…010](../../subtitle-translation/spec.md) |
| Реестр, загрузка, локальные ресурсы и изоляция | [MODEL-001…009](../../model-runtime/spec.md) |
| Локальная граница, выбор файлов и состояние веб-задачи | [WEB-001…005](../../local-web/spec.md) |

Внутренние параметры и пути проверяются по ссылкам на конфигурацию и реализацию из соответствующей спецификации.
