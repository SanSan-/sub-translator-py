# Дополнительные правила sub-translator-py

Обязательно вместе с [общим профилем](python-common.md). Предметные правила находятся в соответствующих capability.
Прямые указания в текущей задаче имеют приоритет. Существенную неоднозначность сначала проверяй по коду и принятым
решениям; зависимое решение уточняй, продолжая независимую работу.

## Работа с кодом и документацией

- Русские комментарии, docstring и сообщения сохраняют устойчивый стиль файла. Существующие сообщения журналов не
  изменяй без необходимости задачи; форматирование и окончания строк вне изменения сохраняй.
- Ищи готовую реализацию; разделяй формат, подготовку пачек, перевод, восстановление, кеш и инфраструктуру. Небольшая
  функция решает один вопрос; 40–50 строк — ориентир ясности, не повод ослаблять контракт. Общие значения именуются;
  лишние преобразования на горячем пути не размножаются.
- CLI и веб используют единый сервис; пользовательская ошибка по-русски без диагностической трассировки как основного
  ответа. Не расширяй задачу интерфейсной переделкой и несогласованными функциями.
- Новые требования/планы/долговечные наблюдения веди в OpenSpec; новые датированные evidence — в change. README
  сохраняет переносимое руководство, CHANGELOG — значимые выполненные изменения в разделе «Не выпущено». Не объявляй
  планы выпущенными изменениями.
- При изменении окружения обновляй имя и переносимый пример в .env.example и пользовательской справке README. Локальные
  значения, пути модели и токены не публикуй. При изменении контракта синхронизируй capability, примеры, словарь, ADR и
  ссылки в том же цикле. Диаграмма находится рядом с описываемым процессом.

## Среда и команды

Версия: `sub_translate.__version__ = 0.2.3`; метаданные получают её динамически. CLI, health/OpenAPI, Sonar и история
должны совпадать с этим источником при изменении версии. Основная среда: CPython `>=3.14,<3.15`, .python-version=3.14.
`tool.uv` ограничен CPython/Windows/AMD64. Изолированные профили используют только декларативные зависимости своего
реестра.

Прямые runtime/dev зависимости закреплены точно в pyproject.toml; единый граф — uv.lock, отдельных requirements нет.
Сейчас Torch 2.13.0+cu130, Transformers 5.14.1, FastAPI 0.141.1; полный состав берётся из манифеста, а не дублируется
словами. Добавление зависимости требует проверки lock, чистой/проверяемой среды, совместимости, импортов и реального
CLI/веб-запуска по объёму задачи.

Команды из корня проекта; они описаны для последующей работы и выполняются только в соответствующей задаче:

```powershell
uv lock --check
uv sync --frozen
uv pip check
uv run --frozen python -m pytest -p no:cacheprovider -q
uv run --frozen python -m pytest -p no:cacheprovider -q --cov=sub_translate --cov-branch --cov-report=term-missing --cov-report=xml:coverage.xml
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen python -B -m compileall -q sub_translate tests tools
uv build
node --check sub_translate/web/static/app.js
```

Браузерный набор: из `tests/e2e` — `npm test` в подготовленной среде. Рабочая установка без dev —
`uv sync --frozen --no-dev`. Сначала узкий изменённый контракт, затем полный основной набор. При изменении JavaScript
нужны синтаксис и применимый браузерный сценарий. Невоспроизводимый результат алгоритма требует теста и первичных данных
в `docs/benchmarks` со ссылкой из evidence.

Реальные модели/API не входят в обычный набор. Для тяжёлых TranslateGemma 12B/Seed-X используется
`RUN_HEAVY_LOCAL_MODEL_INTEGRATION=1` и пять соответствующих параметров из .env.example; существующие integration-тесты
других профилей сохраняют собственные условия. Не запускай эти режимы для документов. Метрики качества требуют
одинакового корпуса EN↔RU, структуры/имён/терминов/BLEU/chrF++, времени и RAM/VRAM, preflight, выхода через общий
сервис, кеш-повтора, выгрузки и безопасного отказа. Лицензия/совместимость/ресурсы фиксируются до добавления модели;
внешний рейтинг не заменяет сравнение.

Sonar после стабилизации кода: свежий XML покрытия и sonar-scanner из корня; SONAR_TOKEN только через окружение, не
-Dsonar.token. Дождись фактической задачи вычислительного движка и Quality Gate, проверь SECURITY, ошибки, уязвимости,
сопровождаемость и дублирование. Не расширяй исключения и не снижай порог (coverage fail_under=65) ради результата.
После исправлений повтори набор и новый анализ; сохрани дату, команды, ID и ограничения в evidence. Для открытой задачи
transport retry принят отдельный охват: локальные проверки без SonarQube.

## Предметные уточнения

- Настройки: defaults → .env → process env → явный интерфейс; неприменимые поля не влияют на кеш, неизвестные веб-поля
  отклоняются, пустые необязательные пути нормализуются в null.
- Google разрешает только `ca, co.in, co.jp, co.kr, co.uk, com, com.au, com.br, com.mx, de, es, fr, it, nl, pl, pt, ru`.
  OpenAI получает OPENAI_API_KEY непосредственно перед клиентом; модель выбирается TRANSLATOR_AGENT_MODEL/явным
  параметром, подписи подсказок входят в кеш без текста и секрета.
- Готовый кеш использует алгоритм subtitle-output-v4, подпись источника/формата/языков/профиля/модели/ревизии/полного
  содержимого/значимых настроек/подсказок. В кеш не записывается результат изменившегося источника. Ограничения и версии
  двух кешей независимы; преобразование неизвестного формата не выполняется скрытно. Фрагментный кеш сохраняет время
  создания/использования, ограничивает возраст/число/размер и объединяет изменения под блокировкой.
- При временном PermissionError атомарная замена повторяется до шести раз с возрастающей короткой задержкой; ошибка
  статистики после успешного ответа становится предупреждением. Это не прикладная политика повторов APIConnectionError.
- Полный ручной каталог модели без отметки или с прежней совместимой отметкой используется локально с неподтверждённой
  ревизией. Неполный без отметки загружается принудительно в тот же путь; недействительная отметка или любая отметка
  неполного каталога требует соседнего staging. При двойной системной ошибке сохраняется .backup-* с точным путём в
  ModelAcquisitionError; не обещай существующую цель после такого сбоя.
- Реестр хранит модель/revision/путь/обязательные файлы/альтернативы весов/языки/лицензию/первичный
  источник/ресурсы/токены/среду. Seed-X — ByteDance-Seed/Seed-X-PPO-7B, revision
  6ef78fc034ec86c0036d7a7ca2bfc24607f48050, models/seed-x-ppo-7b; старый AWQ-каталог не удаляется и не используется
  новым профилем. Остальные точные ревизии — из реестра.
- Рабочий процесс использует bounded UTF-8/JSON с ID, version и командами translate/preflight/unload/ping/shutdown по
  возможностям. Stdout только протокол, stderr дочернего процесса не копируется пользователю; удаляются секретные
  переменные. psutil завершает точное дочернее дерево. Нельзя завершать чужие задачи.
- Веб: один тяжёлый слот, локальные пути через системный диалог; до 10000 элементов, до 200 карточек, ограниченные
  снимки и журналы. Снимок задачи авторитетен при SSE-потере/нескольких вкладках. Терминальное состояние означает
  опубликованный проверенный выход либо явную ошибку, не просто завершённый HTTP-запрос.

## Завершение

Весь согласованный объём реализован, обязательные проверки прошли, относящиеся к задаче пункты завершены, спецификация
синхронизирована и доказательства сохранены. Если часть не выполнена, сообщи точный RED/NOT_RUN/partial и следующий шаг;
узкий успех не заменяет весь критерий. Для изменения документации действуют только её документальные критерии.

## Автоматические правила контекста

Обязательны [SEC-CONTEXT-001…004](../spec.md) и [CTX-005…008](../../project-context/spec.md): проверка существенного
плана, безопасные входы и передача, событийная сводка, ограниченный вывод, восстановление и смысловая дельта. Аудит
CTX-009 применяется только по отдельному явному запросу с заданной областью проверки. Локальный инженерный профиль
описан в python-common.md.

Датированные доказательства хранятся в соответствующем изменении. Отдельный аудит требует явного запроса с заданной
областью проверки. Полные процедуры навыков остаются в SKILL.md.
